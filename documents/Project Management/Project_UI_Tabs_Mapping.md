# Project Navigation UI & Tab Architecture

This document extends the core project architecture by mapping out the primary user interface navigation tabs found in the `ProjectHeader.vue`. It details the component path, the corresponding route, and the underlying business logic that powers each tab. 

The Project Dashboard exposes 10 core tabs to the end-users:

## 1. Overview
*   **Purpose**: The central dashboard summarizing project health, milestone progress, and high-level metrics.
*   **Route**: `projects.show` (handled by `ProjectController@show`)
*   **Component**: `Pages/Project/Show.vue` (or `Dashboard.vue`)
*   **Data Flow**: Pulls aggregate statistics from `Project` relationships (`tasks`, `sprints`, `bugs`). Provides the 10,000-foot view required by managers and directors.

## 2. Board
*   **Purpose**: The operational Kanban board where individual task cards are dragged across lifecycle stages.
*   **Route**: `projects.board` (handled by `ProjectController@board` or `TaskController@board`)
*   **Component**: `Pages/Project/Board.vue`
*   **Data Flow**: Requires a heavily nested response containing `Task` models joined with `Assignees` and `Tags`. A `<draggable>` or custom Vue transition component is used here. Triggers `TaskController@update` on column drops.

## 3. List
*   **Purpose**: A high-density data table representation of tasks, suitable for bulk editing and rapid scanning.
*   **Route**: `projects.tasks.index` (handled by `TaskController@index`)
*   **Component**: `Pages/Project/Task/Index.vue`
*   **Data Flow**: Implements standard data tables mapping over `project_tasks` with advanced sorting and filtering capabilities (e.g., filtering by Priority, Sprint, or Status).

## 4. Modules
*   **Purpose**: For large-scale projects, work is broken down into thematic Modules (e.g., "Frontend", "Database Schema").
*   **Route**: `projects.modules.index` (handled by `ProjectModuleController@index`)
*   **Component**: `Pages/Project/Module/Index.vue`
*   **Data Flow**: Relies on the `ProjectModule` model. Tasks and bugs are often bound to specific modules, allowing PMs to gauge progress per independent project slice.

## 5. Visual Planner
*   **Purpose**: Advanced timeline mapping and team-wide capacity management.
*   **Route**: `planner.index` (handled by `PlannerApiController@index` / `PlannerController@index`)
*   **Component**: `Pages/Project/Planner/Index.vue`
*   **Data Flow**: This is a powerful, heavy module containing multiple sub-views (GanttChart, ResourceMatrix, etc.). It analyzes overlaps across `start_date` and `due_date` across all Sprints and Tasks.

## 6. Bug Tracker
*   **Purpose**: Dedicated interface for Quality Assurance and Client-Reported defects.
*   **Route**: `bugs.index` (handled by `BugTrackerController@index`)
*   **Component**: `Pages/Project/BugTracker/Hub.vue`
*   **Data Flow**: Specifically maps to the `bug_tickets` table, completely bypassing standard task flow to enforce SLA timers and environment metadata rules.

## 7. Documents
*   **Purpose**: Centralized storage for project-related files (MOMs, DFDs, Contracts).
*   **Route**: `projects.files` (handled by File/Document controllers)
*   **Component**: `Pages/Project/File/Index.vue` (or Planner view reference)
*   **Data Flow**: Manages `ProjectDocument` models with strict visibility rules indicating whether a file is `team`, `public`, or `private`. Integrates heavily with cloud/local file systems.

## 8. Reports
*   **Purpose**: Generation of analytics, sprint retrospectives, and client PDFs.
*   **Route**: `projects.reports` (handled by `ReportController@index`)
*   **Component**: `Pages/Project/Reports.vue`
*   **Data Flow**: Pulls historical logs (`task_activities`, `SprintLog`), passing them through processing services to export downloadable insights.

## 9. Templates
*   **Purpose**: Scaffolding for redundant or highly repeated task structures (e.g., "New Server Setup Checklist").
*   **Route**: `projects.templates.index` (handled by `TaskTemplateController@index`)
*   **Component**: `Pages/Project/Template/Index.vue`
*   **Data Flow**: Maps over `TaskTemplate` models. An action payload duplicates these templates into live `Task` entities within a Sprint.

## 10. War Room
*   **Purpose**: High-intensity, auto-refreshing dashboard utilized during critical deployment phases or major outages.
*   **Route**: `projects.warroom` (handled by customized real-time controller logic)
*   **Component**: `Pages/Project/WarRoom.vue`
*   **Data Flow**: Subscribes to real-time events via Pusher/WebSockets to monitor `BugTicket` escalation, failed deployments, and system health metrics instantly.
