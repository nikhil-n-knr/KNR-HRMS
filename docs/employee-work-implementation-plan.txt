Employee Workbench Completion Plan
Date: 2026-04-15
Status: Phase 1 + core Phase 2/3 completed, hardening pending

Objective
Deliver a production-safe employee-only execution desk for:
1) My Tasks
2) My Bugs

Employees can perform only restricted execution actions (status, move-next, comments, checklist toggles, drift submission) with strict assignment-based authorization and no board-level administrative edits.

Completed Baseline

- Navigation links to My Work exist (profile and personal hub).
- Restricted employee endpoints exist for:
  - task status update
  - task move-next
  - task comments
  - task checklist toggle
  - bug status update
  - bug comments
  - task drift submit
  - bug drift submit
- TaskPolicy and BugTicketPolicy are implemented and registered.
- My Work page now has actionable controls (status/comment/checklist/drift).

Corner Case Matrix (must be handled)

A. Authorization and data leakage
- Employee tries action on unassigned task/bug -> return 403.
- Employee guesses another checklist ID under same task route -> return 404/403.
- User has role upgrade or assignment revoked during active session -> enforce latest DB state on each action.

B. Stage transitions
- Task has no next stage but move-next requested -> 422 with clear message.
- Submitted stage_id not in task project stages -> 404/422.
- Bug stage from unrelated workflow accepted accidentally -> reject via scoped validation.

C. Drift submission
- days_added=0 and hours_added=0 -> reject 422.
- Missing reason or too short reason -> reject 422.
- Invalid category -> reject 422.
- Extended date before original date -> reject 422 unless explicitly allowed by policy.
- Duplicate rapid drift submissions -> idempotency guard or debounce at UI.

D. Comment and checklist
- Empty comment or whitespace-only -> reject 422.
- Checklist toggle on already stale row (deleted item) -> return 404 gracefully.
- Concurrent toggles from two users -> last write wins, UI reloads authoritative state.

E. Frontend state and transport
- CSRF token missing/expired -> redirect or standardized auth error handling.
- Partial reload race after rapid actions -> queue refresh or optimistic update with rollback.
- Network timeout -> surface retry option and do not clear draft inputs.

F. Data integrity
- project_extensions.task_id nullable handling for bug drift with no linked task.
- task_checklists.assigned_to type standardization (users vs employees) must be consistent across policy and controller checks.

Acceptance Criteria
1) Employee can act only on assigned tasks/bugs.
2) All action endpoints return deterministic errors for invalid input/authorization.
3) Drift always saved with category, metadata source, actor, and review status.
4) Test suite covers all critical and corner cases listed in P0.
5) No diagnostics errors in touched files.
